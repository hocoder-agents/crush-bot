# AGENTS.md

Guidance for AI agents working in this repository.

## What this is

**crushbot** (Go binary, module `github.com/hocoder-agents/crush-bot`) is a Charm Crush powered bot mesh: a roster of named [Crush](https://github.com/charmbracelet/crush) workspaces (bots) that DM each other, hand off tasks, and sit in group rooms. crushbot is a **host** that wraps the external `crush` binary (≥ 0.91.2) — it never imports Crush as a Go library and never patches it.

Primary references:
- `DESIGN.md` — the full product spec (key decisions K1–K22, data layout, transport model). Read this before any design-level change.
- `docs/mesh.md`, `docs/mesh-model.md`, `docs/soul.md` — shorter topical docs.
- `README.md` — operator-facing usage.

## Commands

```bash
go build -o crushbot ./cmd/crushbot   # build
go test ./...                          # tests
go vet ./...                           # vet
go mod tidy
scripts/e2e-mesh.sh                    # two-bot e2e smoke with a FAKE crush (no provider needed)
```

There is a `Taskfile.yaml` (`task` default/test/vet/tidy) wrapping the same commands. There is no linter config beyond `go vet`.

`scripts/e2e-mesh.sh` builds a throwaway binary, puts `internal/crush/testdata/fake-crush.sh` on `PATH` as `crush` (state under `FAKE_CRUSH_STATE`), and runs with throwaway `CRUSHBOT_HOME` and `XDG_CONFIG_HOME`. Use it to verify daemon/mailbox behavior without a provider login.

## Architecture

`cmd/crushbot/main.go` → `internal/cli.Main`, an in-repo **argv router** (~100-line switch) + stdlib `flag`. **No cobra, no fang, no pflag** — this is a deliberate design decision (K10). CLI verbs return process exit codes; `cli.IO{In,Out,Err}` injects streams for tests.

Package map (`internal/`):

| Package | Role |
| --- | --- |
| `config` | Global config (`XDG_CONFIG_HOME/crushbot/config.yaml`), `CRUSHBOT_HOME` paths, defaults |
| `roster` | Bot records (`bot.yaml`), slug validation, `$CRUSHBOT_HOME/bots/<slug>/` homes |
| `soul` | `soul.md` seed + scan |
| `spawn` | Bot creation (Huh form in a TTY, flags otherwise); applies shipped presets |
| `preset` | Embedded default bots (`souls/manifest.yaml` + soul `.md` files) |
| `lock` | `flock`-based `turn.lock` |
| `crush` | Runs external `crush` (runner args, keep-alive server host, `--yolo`/`--debug`) |
| `envelope` | Inbox JSON message shape |
| `daemon` | Courier: polls inboxes (200 ms), wakes `crush run --session <uuid>`, PID file, JSON logs |
| `mesh` | MCP **stdio JSON-RPC server** (`crushbot mcp`) exposing inter-bot tools |
| `protocol` | Generates per-bot `crushrc`, `crushrc.d/`, `protocol.md`, `CRUSH.md`, hooks |
| `group` | Group rooms, serial rounds |
| `task` | Durable file task queue |
| `sandbox` | bwrap / Landlock sandbox wrapping for `--coder` bots |
| `cli` | argv router + all headless verbs |
| `ui` | Bubble Tea mesh TUI (roster + session transcript) |

Control flow for a DM: `crushbot mention A B "…"` (or bot B calls MCP `message_bot` while A runs) → JSON envelope written to `bots/B/inbox/pending/` → daemon (polling) picks it up, takes B's `turn.lock`, runs `crush run --cwd B_HOME --data-dir B_HOME/.crush --session <canonical-uuid> "…"` → envelope archived, optional `kind: receipt` to sender. Tasks are a separate durable queue (MCP `assign_task`); groups use per-membership session UUIDs in `bot.yaml.group_sessions`.

## Critical invariants and gotchas

These encode non-obvious decisions; breaking them causes subtle failures:

- **A bot is a directory**: `$CRUSHBOT_HOME/bots/<slug>/` with `soul.md`, `bot.yaml`, `.crush/` (Crush SQLite data dir), `inbox/`, `tasks/`. Default home is `~/.local/share/crushbot`, overridable via `CRUSHBOT_HOME`.
- **`--cwd` is always the bot home**, never a project directory. Crush discovers config **from cwd** (`$BOT_HOME/crushrc`), not from `--data-dir`. Mixing a project cwd silently drops the mesh MCP tools, soul injection, and deny-lists. `bot.yaml.project` is only advisory text handed to the model.
- **One exclusive `turn.lock` per bot** for *any* Crush process (daemon wake, `say`, `chat`). Two Crush processes on one `--data-dir` corrupt the session SQLite DB. Runners may accept a pre-held lock (`RunOpts.HeldLock`).
- **Mailbox-and-wake, not long-lived processes**: idle bots have no Crush process. The daemon is required for mesh DM/task delivery; `say`/`chat` work without it.
- **Hop/anti-loop context lives in `$BOT_HOME/turn.json`**, written by the host before every spawn; MCP reads it. Models must never supply hop counts as tool params.
- **`soul.md` is user-owned**: seeded once at spawn, never overwritten. The mesh protocol lives in generated `protocol.md` (regenerated, not user-edited); `crushrc` and generated files carry the header "generated by crushbot — do not edit".
- **Crush permissions: `deny` hides a tool; an allow-list alone still prompts** and hangs unattended `crush run`. Unattended bots must `permissions deny` hidden tools (default: `bash`, `edit`).
- **Sandbox is Linux-only** (bwrap preferred, Landlock fallback) and **required whenever a bot enables `bash` or `edit` tools**; fail closed unless `bot.yaml.sandbox: off`. Landlock rules need careful RO/RW path grants (see recent commit history — `/dev/null`, XDG dirs, npm Crush package dir were all needed).
- **Slugs only**: `^[a-z][a-z0-9-]{0,62}$` (no title-derived aliases). Hops bounded at `max_hops` (default 8) + fan-out; no path-cycle reject (the target must be able to reply, so `to ∈ trace` is not an error).
- **Shipped preset bots** (`researcher`, `coder`, `reviewer`) live in `internal/preset/souls/` and are embedded into the binary; `spawn <preset-slug>` seeds the preset soul/title/role (flags override), and `crushbot crew` spawns every preset missing from the roster. Clone (`--clone-from`) beats presets.
- **Keep-alive**: optional `crush server` per bot on `unix://$BOT_HOME/crush.sock`; the runner passes `--host` only when the socket is live (`ServerLive`).
- The minimum Crush version (0.91.2) is a hard floor pinned in `internal/config` (`MinCrushVersion`); `doctor` checks it.

## Testing patterns

- Standard Go tests next to code (`*_test.go` in each package).
- CLI verbs are tested through `cli.IO` injection, not os.Stdout.
- The fake Crush (`internal/crush/testdata/fake-crush.sh`, keyed by `FAKE_CRUSH_STATE`) stands in for the real binary in tests and e2e — run tests without Crush installed.
- Group/mesh behavior tests use temp `CRUSHBOT_HOME` trees built in-process.

## Conventions

- Charm stack only: `charm.land/bubbletea/v2`, `lipgloss/v2`, `bubbles/v2`, `huh/v2`. UI styling lives in `internal/cli/style.go` and `internal/ui/brand.go`; CLI output is Lip Gloss-styled and degrades when not a TTY (`--plain` / non-TTY → table/plain output).
- Config files are YAML (`yaml.v3`); on-disk state is JSONL/JSON with 0600/0700 permissions (`os.MkdirAll(..., 0o700)` is the norm — this is a single-user secrets-adjacent surface).
- Docs are part of the product surface (README, DESIGN.md, docs/): keep them in sync when changing CLI verbs, flags, or the mesh model. Recent history shows docs fixed after TUI/daemon changes.
